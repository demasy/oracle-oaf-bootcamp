## Course Description

This comprehensive bootcamp provides a **scaffold-oriented**, hands-on learning experience in Oracle Application Framework (OAF) development. Using structured support that gradually fades as competency grows, students will master OAF from foundational concepts to advanced implementation and real-world project development.

The course employs a **scaffolded learning approach** with:
- **"I Do, We Do, You Do"** progression in every section
- Structured support that decreases as mastery increases
- Progressive complexity with layered guidance
- Gradual release of responsibility
- Practical, hands-on exercises with decreasing instructor involvement
- Real-world project implementations with increasing autonomy
- Self-assessment and reflection at each stage

---

## Course Philosophy & Pedagogical Approach

### Evidence-Based Learning Framework

This bootcamp is designed using:

1. **Scaffolding Framework (Primary)** - Gradual release of responsibility using the "I Do, We Do, You Do" model
2. **Zone of Proximal Development** - Learning activities designed just beyond current capability with support
3. **Bloom's Taxonomy** - Progressive cognitive development from remembering to creating
4. **Constructivist Learning** - Building knowledge through hands-on practice
5. **Deliberate Practice** - Focused, repetitive practice with decreasing guidance and increasing feedback
6. **Project-Based Learning (PBL)** - Real-world application development with staged autonomy
7. **Mastery Learning** - Proficiency before progression to next scaffold level

### Scaffold-Oriented Design Principles

#### The "I Do, We Do, You Do" Progression

Every section follows this gradual release model:

1. **"I Do" (Modeling)** - Instructor demonstrates with full explanation
   - Live coding demonstrations
   - Annotated examples
   - Step-by-step walkthroughs
   - Thinking aloud process

2. **"We Do" (Guided Practice)** - Collaborative work with instructor support
   - Paired programming exercises
   - Instructor-guided labs with checkpoints
   - Real-time feedback and correction
   - Scaffolded activities with hints available

3. **"You Do" (Independent Practice)** - Student works with minimal support
   - Solo labs and exercises
   - Self-directed problem solving
   - Optional hints (must try first)
   - Self-assessment and debugging

#### Progressive Support Reduction

- **Level 101:** High support (60% guided, 40% independent)
- **Level 102:** Moderate support (40% guided, 60% independent)
- **Level 103:** Minimal support (20% guided, 80% independent)

#### Scaffolding Strategies Used

- **Procedural Scaffolds:** Templates, checklists, step-by-step guides (fade by Level 103)
- **Conceptual Scaffolds:** Diagrams, concept maps, references (available throughout)
- **Strategic Scaffolds:** Problem-solving frameworks, debugging strategies (emphasized then internalized)
- **Metacognitive Scaffolds:** Reflection prompts, self-monitoring tools (increased responsibility over time)

## Scaffold-Oriented Teaching Strategies

### 1. **Gradual Release of Responsibility (Primary Framework)**

**Phase 1: Full Support ("I Do")**
- Instructor models the complete task
- Think-aloud demonstrations
- Annotated code examples
- Video recordings for review

**Phase 2: Shared Responsibility ("We Do")**
- Paired/group work with instructor circulating
- Guided labs with checkpoints and validation
- Interactive problem-solving sessions
- Immediate corrective feedback

**Phase 3: Independent Work ("You Do")**
- Solo practice with optional scaffolds
- Self-directed debugging
- Minimal instructor intervention
- Peer support encouraged

### 2. **Layered Complexity with Temporary Supports**

**Level 101: Maximum Scaffolding**
- Detailed step-by-step instructions
- Code templates provided
- Frequent checkpoints
- Immediate help available
- Solution code provided after attempt

**Level 102: Moderate Scaffolding**
- High-level instructions
- Partial templates
- Milestone checkpoints
- Self-service help resources
- Solution code after completion

**Level 103: Minimal Scaffolding**
- Requirements only
- Architecture guidance only
- Major milestone reviews
- On-demand consultation
- No solution code (real-world simulation)

### 3. **Structured Problem-Solving Framework**

**Scaffold Provided:**
1. Understand (questions to ask)
2. Plan (approach framework)
3. Implement (coding checklist)
4. Test (test scenarios provided)
5. Debug (debugging decision tree)
6. Reflect (reflection prompts)

**Fading Process:**
- Level 101: All steps guided with examples
- Level 102: Framework provided, execution independent
- Level 103: Internalized, self-directed use

### 4. **Differentiated Support Levels**

**For Every Lab/Exercise:**
- **Level 1 (Beginner):** Complete walkthrough available
- **Level 2 (Intermediate):** Hints and checkpoints
- **Level 3 (Advanced):** Requirements only
- Students choose their support level based on comfort

### 5. **Just-In-Time Learning Resources**

**Accessible When Needed:**
- Quick reference cards (always available)
- Code snippet library (searchable)
- Common error solutions (troubleshooting guide)
- Video mini-lessons (concept review)
- Office hours (personalized support)

### 6. **Reflective Practice with Decreasing Prompts**

**After Each Activity:**
- **Level 101:** Structured reflection with specific questions
- **Level 102:** Open-ended prompts
- **Level 103:** Self-directed reflection and documentation

### 7. **Peer Scaffolding and Community Support**
- Expert students mentor beginners
- Collaborative debugging sessions
- Code review partnerships
- Knowledge sharing presentations
- Creating a learning community that provides mutual support

### 8. **Error-Based Learning with Progressive Independence**

**Level 101:**
- Instructor-created errors to debug (guided)
- Debugging checklist provided
- Solution walkthrough

**Level 102:**
- Student-generated errors to debug
- Debugging framework reference
- Peer consultation

**Level 103:**
- Real-world debugging scenarios
- Self-directed problem solving
- Documentation of solutions
